# 网上综合书店销售数据库项目
## 需求分析（与汇报 PPTX 对齐版）

> 文档用途：作为 ER 图、表结构、SQL 脚本与后端实现的数据库需求依据。
> 对齐来源：`pre/网上综合书店销售数据库_展示(6).pptx`。

---

## 1. 项目背景与目标

本项目设计并实现一个综合性的网上书店销售数据库系统，用于管理连锁门店、商品与图书、供应商、客户会员、销售记录、采购入库、门店库存、权限控制和统计分析。

数据库层面重点解决：

- 实体划分、关系基数、关系模式转换；
- 主键、外键、唯一、非空、CHECK 等完整性约束；
- 门店维度库存沉淀；
- 采购入库到库存、库存到销售扣减的业务链路；
- 基于角色的访问控制数据设计；
- 统计分析视图与聚合查询支撑。

---

## 2. 业务范围

| 模块 | 业务内容 | 数据关注点 |
|---|---|---|
| 门店管理 | 维护连锁门店信息 | 门店名称、城市、地址、电话、负责人 |
| 供应商管理 | 维护供货商及供货关系 | 供应商名称、联系人、电话、邮箱、合作状态、供货价 |
| 商品管理 | 维护可销售商品 | 商品名称、分类、计量单位、售价、在售状态 |
| 图书管理 | 管理图书专有信息 | ISBN、出版社、作者、译者、版次、页数 |
| 出版社管理 | 维护出版社信息 | 名称、联系人、电话、邮箱、地址 |
| 客户会员管理 | 管理客户与会员体系 | 客户姓名、联系方式、地址、会员等级、积分 |
| 销售管理 | 记录交易过程 | 销售主单、销售明细、支付方式、金额、库存扣减 |
| 统计分析支撑 | 为报表提供数据基础 | 销量、销售额、会员消费、商品热度、库存预警 |
| 权限控制 | 支撑后台不同角色访问 | 用户、角色、权限点、角色权限 |
| 采购入库 | 记录采购与到货入库 | 采购单、采购明细、入库单、入库明细 |
| 门店库存 | 按门店和商品维护库存 | 当前库存、安全库存、更新时间 |

暂不重点覆盖：复杂促销引擎、退货退款全流程、物流配送履约、仓库调拨细节。

## 4. 关系与业务语义

| 关系 | 基数 | 业务含义 |
|---|---|---|
| `Store` -> `Sale` | 1 : N | 一个门店产生多笔销售 |
| `Customer` -> `Sale` | 1 : N（可空） | 销售可为会员/客户，也可为散客 |
| `Sale` -> `Sale_Item` | 1 : N | 一笔销售包含多条明细 |
| `Product` -> `Sale_Item` | 1 : N | 商品可出现在多笔销售明细中 |
| `Category` -> `Product` | 1 : N | 一个分类下有多个商品 |
| `Supplier` <-> `Product` | N : M | 通过 `supplier_product` 维护供货关系 |
| `Product` -> `Book` | 1 : 0..1 | 只有图书类商品才有图书子表记录 |
| `Publisher` -> `Book` | 1 : N | 一个出版社可出版多本书 |
| `Book` <-> `Author` | N : M | 一本书可多作者 |
| `Book` <-> `Translator` | N : M | 一本书可多译者或无译者 |
| `Customer` -> `Member` | 1 : 0..1 | 客户可升级为会员 |
| `System_User` <-> `Role` | N : M | 一个用户可拥有多个角色 |
| `Role` <-> `Permission` | N : M | 一个角色拥有多个权限点 |
| `Supplier` -> `Purchase_Order` | 1 : N | 一个供应商可对应多张采购单 |
| `Store` -> `Purchase_Order` | 1 : N | 采购落到具体门店 |
| `Purchase_Order` -> `Purchase_Order_Item` | 1 : N | 一张采购单包含多条采购明细 |
| `Purchase_Order` -> `Stock_In` | 1 : 0..N | 采购到货后可生成入库单 |
| `Stock_In` -> `Stock_In_Item` | 1 : N | 一张入库单包含多条入库明细 |
| `Store + Product` -> `Inventory` | 1 : 1 | 每个门店-商品组合维护一条库存 |
| `Sale_Item / Stock_In_Item` -> `Inventory` | N : 1 | 销售扣减库存，入库增加库存 |

## 5. 关键业务规则

1. 商品必须属于某个分类。
2. 图书必须具备唯一 ISBN。
3. 图书与商品采用共享主键，会员与客户采用共享主键。
4. 销售必须绑定门店，客户可空以支持散客。
5. 销售明细保存成交单价快照，不受后续商品调价影响。
6. 库存不放在 `product`，而是按 `inventory(store_id, product_id)` 维护。
7. 创建销售明细时应按销售门店扣减对应库存。
8. 采购单记录供应商、门店、创建用户、状态和总额。
9. 入库单审核通过后增加对应门店库存。
10. 统计分析不单独存冗余报表表，优先基于视图或聚合查询实现。
11. 后台权限按用户、角色、权限点建模，查询用户只读统计分析。

## 6. 合法值与完整性规则

| 字段类型 | 规则 |
|---|---|
| 价格字段 | `> 0` |
| 数量字段 | `> 0` |
| 库存字段 | `>= 0` |
| 安全库存字段 | `>= 0` |
| 金额字段 | `>= 0`，明细金额等于数量乘单价 |
| 积分字段 | `>= 0` |
| 必填业务字段 | `NOT NULL` |
| 唯一业务字段 | ISBN、会员编号、用户名、权限编码、门店名、分类名等 `UNIQUE` |
| 状态枚举 | 供应商、客户、商品、采购单、入库单、用户状态需限制合法值 |

## 7. 统计分析说明

统计分析属于查询能力，基于交易与库存数据动态汇总：

| 分析目标 | 来源表 | 实现方式 |
|---|---|---|
| 销量/销售额趋势 | `sale`、`sale_item` | 按 `sale_time` 分组聚合 |
| 商品热度 | `sale_item`、`product`、`book` | 按 `product_id` 汇总销量和销售额 |
| 门店表现 | `store`、`sale`、`sale_item` | 按 `store_id` 汇总订单量、销售额、客单价 |
| 会员消费 | `customer`、`member`、`sale` | 按客户汇总消费频次与金额 |
| 库存预警 | `inventory`、`product`、`store` | 当 `stock_qty <= safety_stock_qty` 时进入预警 |

## 8. 设计原则

- 满足第三范式（3NF），减少冗余与更新异常。
- 表名和字段名统一使用 `snake_case`。
- 主键统一命名为 `xxx_id`，中间表使用复合主键。
- 支持后续增加新商品子类、营销模块、库存扩展和更多统计报表。
- 权限、采购、入库、销售、库存关系全部外键化，防止孤儿数据。
